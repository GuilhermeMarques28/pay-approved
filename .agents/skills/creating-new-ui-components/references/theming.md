# Theming With Uniwind And Tailwind Tokens

Reference based on the Uniwind documentation at https://docs.uniwind.dev/llms-full.txt.

## Goal

Use Tailwind/Uniwind theme tokens as the styling contract for universal UI components. Components should consume semantic color classes such as `bg-bg-primary`, `text-content-primary`, `border-border-primary`, or `bg-feedback-success-low-bg` instead of hardcoded hex values.

The token source for Trix is `foundation-trix.json` → `src/constants/generated/foundation.css` (generated by `yarn constants:foundation`). Do not edit the CSS file by hand.

## Setup

```css
@import 'tailwindcss';
@import 'uniwind';
@import './src/constants/generated/foundation.css';
```

Define design tokens in `global.css` with Tailwind CSS variables:

```css
@theme {
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;

  --spacing-1: 4px;
  --spacing-2: 8px;
  --spacing-3: 12px;
  --spacing-4: 16px;
}
```

Define theme-aware colors with `@layer theme` and `@variant`:

```css
@layer theme {
  :root {
    @variant light {
      --color-background: #ffffff;
      --color-surface: #f9f9f9;
      --color-border: #e5e7eb;
      --color-content-primary: #1b1b1b;
      --color-content-secondary: #474747;
      --color-feedback-success-low-bg: #dcfce7;
      --color-feedback-success-low-content: #16a34a;
    }

    @variant dark {
      --color-background: #070913;
      --color-surface: #111827;
      --color-border: #374151;
      --color-content-primary: #f8f8fa;
      --color-content-secondary: #a8a7b4;
      --color-feedback-success-low-bg: #003516;
      --color-feedback-success-low-content: #d9ffea;
    }
  }
}
```

Tailwind exposes `--color-*` variables as utility classes without `var()` or brackets:

```tsx
<View className="bg-background border border-border rounded-lg p-4">
  <Text className="text-content-primary">Title</Text>
  <Text className="text-content-secondary">Description</Text>
</View>
```

## Component Styling Rules

- Prefer semantic tokens over raw palette tokens in reusable UI components.
- Do not hardcode hex colors in component files unless creating a temporary spike.
- Prefer `className` with Tailwind utilities for normal styling.
- Use `dark:` only for one-off or transitional styling; prefer semantic variables for design system components.
- Keep component logic theme-agnostic. Let Uniwind resolve the active theme.
- Use `@theme static` for tokens that must be readable from JavaScript but may never appear in a `className`.
- Test both light and dark themes for contrast before considering a component done.

## Naming Tokens

Use token names that describe intent, not visual appearance:

```css
/* Good */
--color-content-primary: #1b1b1b;
--color-background: #ffffff;
--color-feedback-critical-low-bg: #ffedd5;
--color-feedback-critical-low-content: #ea580c;

/* Avoid for universal components */
--color-gray-900: #111827;
--color-orange-600: #ea580c;
```

Then consume them through Tailwind classes:

```tsx
<View className="bg-feedback-critical-low-bg border border-feedback-critical-low-content">
  <Text className="text-feedback-critical-low-content">Action required</Text>
</View>
```

Primitive palette tokens can exist in the theme for low-level use, but exported UI components should usually depend on semantic aliases.

## Light And Dark Themes

Uniwind ships with `light`, `dark`, and `system` themes. When only light/dark behavior is needed, components can rely on semantic CSS variables and do not need a `ThemeProvider`.

Prefer:

```tsx
<View className="bg-card border border-border">
  <Text className="text-content-primary">Card title</Text>
</View>
```

Avoid repeating theme variants across design system components:

```tsx
<View className="bg-white dark:bg-gray-900 border-gray-200 dark:border-gray-700">
  <Text className="text-gray-900 dark:text-white">Card title</Text>
</View>
```

The second form is acceptable for prototypes, local screen code, or migrations, but it does not scale as the design system grows.

## Reading Tokens In JavaScript

For most UI styling, use `className`. Only read CSS variables in JavaScript when an API requires raw values, such as charts, maps, animations, native modules, or third-party components.

Use `useCSSVariable` inside React components when the value must update with the active theme:

```tsx
import { useCSSVariable } from 'uniwind';

const [primaryColor, backgroundColor] = useCSSVariable(['--color-content-primary', '--color-background']);
```

Use `Uniwind.getCSSVariable` outside React or inside one-time callbacks. It reads the value once and does not subscribe to theme changes:

```ts
import { Uniwind } from 'uniwind';

export const getPrimaryContentColor = () => Uniwind.getCSSVariable('--color-content-primary');
```

If reading multiple variables with `useCSSVariable`, pass an array instead of calling the hook multiple times.

## Static Theme Variables

Variables read from JavaScript must be available to Uniwind. A variable is available when it is used in at least one `className` or when it is defined in `@theme static`.

Use `@theme static` for values that are not directly used as Tailwind classes:

```css
@theme static {
  --chart-line-width: 2;
  --chart-dot-radius: 4;
}
```

## Custom CSS And Utilities

Use Tailwind utilities directly for simple component styles. Use custom CSS classes or `@utility` only when a repeated pattern would be noisy or impossible to express with utility classes.

```css
@utility h-hairline {
  height: hairlineWidth();
}
```

CSS functions such as `hairlineWidth()`, `fontScale()`, `pixelRatio()`, and `light-dark()` must be defined in `global.css` before use. Do not place those functions directly in `className`.

## Third-Party Components

When a component does not support `className`, prefer wrapping it with `withUniwind` so it can consume Tailwind token classes.

Use `useResolveClassNames` only when a library requires a React Native `style` object and cannot be wrapped. This hook resolves Tailwind class names at runtime, so use it sparingly.
